## Global constraints (apply to every slice)

Copied from the spec; every task's requirements include these.

- **Money:** DB columns are `*_paise bigint`; every API DTO and every web value is a whole-rupee integer with an `_inr` suffix; the `_inr ⇄ paise` mapping lives in `apps/api/src/modules/pg-rent/dto/` and nowhere else; no `_paise` key may appear in any `pg-rent` HTTP response (contract test). Every computed amount is rounded to the nearest whole rupee; splits use largest-remainder rounding (invariant 9).
- **Dates:** all date logic is the IST calendar date. SQL uses `(now() AT TIME ZONE 'Asia/Kolkata')::date`; TypeScript uses `todayIst()` from `apps/api/src/common/date.ts` (created in slice 0). Never `CURRENT_DATE`, never `new Date().toISOString().slice(0,10)`.
- **DB-required:** every `pg-rent` service throws `ServiceUnavailableException({ code: "rent_requires_db", message: "Rent collection requires a database" })` when `DatabaseService.isEnabled()` is false (D13). No in-memory twin.
- **Transactions:** every multi-row write goes through `transaction(db, work, options)` from `apps/api/src/common/transaction.ts`; every mutation writes a `pg_rent_events` row inside the same transaction (invariant 8).
- **Ownership:** every operator call passes through `assertManagedOwnership` (property `operator_id = user AND manage_enabled = true`, `FOR UPDATE` when inside a transaction); every tenant call resolves assignments by `tenant_user_id = me OR (tenant_user_id IS NULL AND occupant_phone_e164 = my phone)` without auto-linking on reads.
- **Validation:** zod schemas at the controller edge, `safeParse` → `BadRequestException({ code: "invalid_payload", message })` exactly as `admin.controller.ts:1314` does.
- **Idempotency:** mutating operator endpoints that create money rows use the existing `Idempotency-Key` header + `IdempotencyService.run(userId, route, key, fn)` pattern from `pg-assignment.controller.ts` **and** persist the key on the row (`idempotency_key` column, unique partial index) so the DB, not only the 24-hour cache, refuses a duplicate.
- **Flags:** `FF_PG_RENT_COLLECTION` (API, `readFeatureFlags().ff_pg_rent_collection`, default false) gates HTTP controllers with 404 `{ code: "feature_disabled" }`. Internal hooks (`onAssignmentEvent`, `onOwnershipTransferred`) are data-driven (settings row exists) and ignore the flag. Web: `NEXT_PUBLIC_FF_PG_WORKSPACE_V2`, `NEXT_PUBLIC_FF_PG_RENT_COLLECTION` via `useFlag`.
- **Migrations:** slice 1a took **0072** (file pair `0072_pg_rent_collection.sql` + `0072_pg_rent_collection.rollback.sql`), slice 1b added `0073_pg_rent_alloc_seq`, slice 1c adds `0074_pg_rent_invoice_idempotency`; the next free number after 1c is **0075**; conventions from 0062/0063 (`DO $$ … EXCEPTION WHEN duplicate_object`, `CREATE TABLE IF NOT EXISTS`, `trigger_set_updated_at`, `ON DELETE CASCADE` from `pg_properties`, `RESTRICT` between money rows). Additive only. No `btree_gist`.
- **Tests:** vitest; DB suites are `describe.skipIf(!process.env.DATABASE_URL)`; pure functions get 100 % branch coverage; every test fails before its implementation exists.
- **Nothing financial is deleted** (D14): payments are reversed, invoices cancelled, receipts voided; lines are hard-deleted only because the `invoice.line_removed` event carries the full line.
- **Strings:** every user-visible string in `apps/web/lib/i18n.ts`, en + hi.
