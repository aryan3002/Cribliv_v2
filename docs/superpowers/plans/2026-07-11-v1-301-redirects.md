# v1 → v2 301 Redirects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permanently (301) redirect every old v1 URL (`/properties/<slug>-<id>`, `/pgs/<…-id>`, `/pgs/<id>`) to its migrated v2 page, so cribliv.com keeps its SEO equity through the cutover.

**Architecture:** A build-time data map (`v1-redirects.generated.json`, produced from the prod `v1_migration_map` table) keyed by the v1 Mongo ObjectId → `{type, v2-uuid, city}`. A pure, edge-safe resolver (`v1-redirect.ts`) extracts the trailing 24-hex ObjectId from a request path and returns the v2 target (or a category fallback). `middleware.ts` calls the resolver first thing and issues a 301. Pure logic is vitest-unit-tested against a fixture; the JSON is data.

**Tech Stack:** Next.js 14 App Router middleware (NextAuth v5 `auth()` wrapper, edge runtime), TypeScript, vitest (`apps/web`), Postgres (`jsonb_object_agg` for generation).

## Global Constraints

- Redirects are **301 permanent** (not 302/307).
- Targets are **`/en`-prefixed** (v1 URLs are un-prefixed; the indexed canonical is the `en` page).
- Match by the **trailing 24-hex Mongo ObjectId** — never the slug (slugs vary).
- The map covers **all 87 migrated listings** (data-driven from `v1_migration_map`, not a hand-curated GSC subset).
- Middleware runs on the **edge**: no Node APIs, no DB, no filesystem — only the statically-imported JSON.
- Unmapped `/properties/*` or `/pgs/*` paths **301 to the category fallback `/en/city/lucknow`** (never 404, never loop).
- `listing_type` enum values are exactly `'flat_house'` and `'pg'`. PG canonical = `/en/pg/<city>/<id>`; everything else = `/en/listing/<id>`.
- PR flow: branch off `origin/master`, squash-merge (per repo convention).

- [ ] **Step 4: Write the minimal implementation**

Create `apps/web/lib/v1-redirect.ts`:

```ts
/**
 * v1 → v2 cutover redirects. Old cribliv.com URLs were
 *   /properties/<slug>-<24hex ObjectId>   (flats)
 *   /pgs/<slug>-<id> | /pgs/<id>           (PGs)
 * Every migrated listing is keyed in v1-redirects.generated.json by that
 * ObjectId. We match on the trailing 24-hex (slugs are not stable) and 301 to
 * the v2 canonical page. Unmapped v1 paths fall back to the city landing page
 * so nothing 404s. Pure + edge-safe: no DB, no Node APIs.
 */
import generated from "./v1-redirects.generated.json";

export type V1RedirectEntry = { t: "listing" | "pg"; id: string; city?: string };
export type V1RedirectMap = Record<string, V1RedirectEntry>;

const FALLBACK = "/en/city/lucknow";

/** True when the path is an old v1 listing/PG URL we own the redirect for. */
function isV1Path(pathname: string): boolean {
  return (
    pathname === "/properties" ||
    pathname === "/pgs" ||
    pathname.startsWith("/properties/") ||
    pathname.startsWith("/pgs/")
  );
}

/** Extract the trailing 24-hex Mongo ObjectId from a v1 path, else null. */
export function extractV1ObjectId(pathname: string): string | null {
  const clean = pathname.replace(/\/+$/, "");
  const m = clean.match(/([a-f0-9]{24})$/i);
  return m ? m[1].toLowerCase() : null;
}

/** Resolve a v1 path to its v2 target using an explicit map (testable core). */
export function resolveV1RedirectWith(pathname: string, map: V1RedirectMap): string | null {
  if (!isV1Path(pathname)) return null;

  const id = extractV1ObjectId(pathname);
  const entry = id ? map[id] : undefined;
  if (!entry) return FALLBACK;

  if (entry.t === "pg" && entry.city) {
    return `/en/pg/${entry.city}/${entry.id}`;
  }
  if (entry.t === "pg") {
    // PG with no known city — fall back rather than build a broken /pg//<id>.
    return FALLBACK;
  }
  return `/en/listing/${entry.id}`;
}

/** Resolve against the build-time generated map. */
export function resolveV1Redirect(pathname: string): string | null {
  return resolveV1RedirectWith(pathname, generated as V1RedirectMap);
}
```

- [ ] **Step 1: Generate the JSON from prod**

```bash
psql "$PROD_DATABASE_URL" -Atc "
SELECT COALESCE(jsonb_object_agg(
  m.v1_id,
  jsonb_build_object(
    't',    CASE WHEN l.listing_type = 'pg' THEN 'pg' ELSE 'listing' END,
    'id',   m.v2_listing_id::text,
    'city', COALESCE(l.city_slug, c.slug)
  )
), '{}'::jsonb)
FROM v1_migration_map m
JOIN listings l              ON l.id = m.v2_listing_id
LEFT JOIN listing_locations ll ON ll.listing_id = l.id
LEFT JOIN cities c           ON c.id = ll.city_id;
" > apps/web/lib/v1-redirects.generated.json
```

`-Atc` = unaligned, tuples-only → the raw JSON object. `COALESCE(l.city_slug, c.slug)` uses the denormalized `listings.city_slug` (migration 0042) and falls back to the `listing_locations → cities` join.
